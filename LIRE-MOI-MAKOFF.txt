GITHUB
Dépôt cible : https://github.com/anderson76389/Music
Tous les fichiers vendor font partie intégrante du projet.
Le workflow MAKOFF Music Android compile une APK de test sur ubuntu-latest.
Télécharger son artifact seulement si le job réussit. La signature debug CI n’est
pas une signature durable : ne pas distribuer ces APK comme mises à jour finales.
Pour une publication durable : créer et sauvegarder une clé privée de signature,
configurer les secrets puis exécuter le workflow Publier les APK stables signés.
Le canal des mises à jour pointe exclusivement vers ce dépôt. Aucune clé privée ni compte de développeur Metrolist n’est fourni.

VALIDATION RESTANTE SUR TÉLÉPHONE
Installation à côté de Metrolist ; lecture sans compte et avec compte ; recherche ;
changement de morceau écran éteint ; téléchargement puis mode avion ; playlists ;
paroles ; sauvegarde/restauration ; widgets ; Android Auto si utilisé.
Valider la résolution EJS locale sur plusieurs morceaux avant toute publication.

QUALITÉ AUDIO
Mode Élevée par défaut pour lecture et téléchargements. Les modes Auto et Basse
restent sélectionnables. Pas de transcodage ajoutant une prétendue qualité. Le moteur
choisit les flux disponibles et garde la prise en charge des flux Premium fournis
à un compte autorisé. La sortie dépend aussi du casque et du codec Bluetooth.

AUDIT D’INDÉPENDANCE
Lire INDEPENDANCE-MUSIC.txt : inventaire des fonctions conservées, de vos secrets
de publication et du serveur d’écoute partagée inclus mais non encore hébergé.
Ces deux APK correspondent à cet audit. Chaque construction de test utilise une
clé temporaire ; une publication durable nécessite votre clé privée conservée.
Sauvegarder les données avant de remplacer une ancienne installation de test.
